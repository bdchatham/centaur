- (decision) Events are derived from durable Absurd state, no event table and no migration: created=t.enqueue_at; started=t.first_started_at when set; retried=one per r_ row of the task with attempt>1 at that row's created_at (fail_run inserts the retry row when the failure is recorded); completed/failed=last attempt row's completed_at/failed_at when task state is completed/failed; cancelled=t.cancelled_at when task state is cancelled
- (decision) A failed attempt that is retried yields a retried event, not a failed event: failed means the run itself ended failed, matching WorkflowRun status
- (capability) CAP-1: client fetches a run's lifecycle events; each entry exactly kind and at; route returns {ok, events}; all four queues; route_access WorkflowsRead
- (capability) CAP-2: events oldest first by at; ties broken by lifecycle order created, started, retried, terminal
- (capability) CAP-3: created and started events; created always present, started only once execution began
- (capability) CAP-4: one retried event per retry attempt of the task
- (capability) CAP-5: terminal event completed, failed or cancelled with at as in WorkflowRun completed_at; none while the run is non-terminal
- (capability) CAP-6: no inputs, results, failure payloads, attempt numbers, or run or task ids in the response
- (capability) CAP-7: unknown run is 404 with ok false and the same error body as the full run endpoint
- (capability) CAP-8: one public reader on WorkflowRuntime returns the events in a type serializing to exactly kind and at; the route returns them unchanged
