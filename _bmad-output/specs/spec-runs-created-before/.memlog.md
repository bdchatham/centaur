- (direction) Input brief (mark bafyreietv6omw..., goal workflow-runs-created-before, human/engineer): add created_before to GET /api/workflows/runs in api-rs, counterpart of created_after with same validation and semantics (RFC 3339 with offset; 400 naming created_before and RFC 3339; compared as instants; bound excluded, strictly earlier); combines with limit, workflow_name, state, created_after; proven by HTTP tests mirroring the created_after suite.
- (event) Mode: headless, express; slug runs-created-before.
- (note) Code read: routes.rs list_workflow_runs parses state then created_after (map_err to ApiError::BadRequest with RFC 3339 message) before workflow_runtime(&state); ListWorkflowRunsQuery in types.rs has created_after: Option<String>; WorkflowRuntime::list_runs_by_state(limit, workflow_name, state, created_after) fans out over 4 queues calling list_runs_for_queue whose SQL has '$4::timestamptz is null or t.enqueue_at > $4', order by t.enqueue_at desc, t.task_id desc, limit; merge, sort, truncate. list_runs calls list_runs_by_state with None. Existing suite: centaur-api-server/tests/runs_created_after_http.rs (5 DB-free 400 tests, 7 DB-backed tests; seeds Absurd queue tables directly).
- (capability) CAP-1: client lists only runs whose created_at is strictly before ?created_before (RFC 3339), newest first.
- (capability) CAP-2: created_before composes with limit, workflow_name, state and created_after; limit counts matching runs; with both bounds only runs strictly between them are returned.
- (capability) CAP-3: a created_before value that is not valid RFC 3339 (garbage, empty, date-only, no offset) is HTTP 400 naming created_before and RFC 3339; absent param behaves as today.
- (constraint) Bound applied in SQL per queue before limit (t.enqueue_at < bound), same as created_after, so limit counts matching runs across all queues.
- (constraint) Strictly earlier: a run created exactly at the bound is excluded; offsets normalised to an instant (10:00:00+02:00 equals 08:00:00Z).
- (constraint) Parse created_before before the workflow runtime lookup, as created_after, so an invalid value is 400 whatever runtime availability; gives DB-free red tests. Invalid created_before stays 400 even with a valid created_after, and vice versa.
- (constraint) Additive only: response shape, ordering, default limit unchanged; no migration; no new index.
- (constraint) Proof via HTTP route only: a new test file centaur-api-server/tests/runs_created_before_http.rs calling GET /api/workflows/runs on build_router_with_session_and_workflow_runtime, using no symbol this work adds, so it compiles before the change and fails since created_before is ignored. Harness helpers may be copied or extracted to a shared tests module; list_runs_by_state shape (extra positional arg vs filter struct) is the dev's choice; edits to existing tests only where the design needs them.
- (decision) One story covers CAP-1..3: parsing, SQL bound and composition are not separately useful, the whole change is a small mirror of created_after, and the DB-free 400 tests give the red; splitting would leave an accepted-but-ignored param between stories.
- (decision) Brief names no checkpoints, so none in stories.yaml.

- (assumption) A bound earlier than every run returns an empty runs list with HTTP 200 (brief: empty result when the bound is earlier than every run).
